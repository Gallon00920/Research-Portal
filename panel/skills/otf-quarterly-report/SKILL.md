# OTF 季度研报 · 生图 + 正文 一条流水线

**目标**：把 Report 文件夹里的 filings 和券商研报变成一份完整的英文 Word 报告，图与正文同源、跨季同款。

**两个阶段中间有一道硬门** —— 图和数必须由用户逐项校对签收，才允许动正文。理由：正文一旦写起来，一个错数会同时污染表格、点评、Summary 回指和跨节引用，改一个数的代价从「重跑 2 分钟脚本」变成「重写半个章节」。

## 缺料：跳过，并从报告里整块删掉（覆盖本 skill 里所有旧的缺件说法）

缺源文件是常态，不是错误。**不问用户、不等补件、不沿用上季值、不写「本季缺 <文件> 输入」这类行。**

1. **先清点**：取数之前，按 `references/01_inputs.md` §1.1 的来源表逐项标「有 / 缺」。本季没有对应文件就算缺；旧季文件绝不冒充当季。
2. **跳过**：只依赖缺件的图、表、小节一律不做，其余照常。
3. **整块删掉，不留痕迹**：删掉的图不留空框、不留小注、不在正文写缺件说明。一小节的图和论据全来自缺件 → 整小节删；一节的小节全删 → 整节删。引用了被删部分的地方一起删：开篇结论、各节点评、Summary 回指、交叉引用。一句话里既有可用证据又有缺件证据的，只留可用的那半。
4. **重新编号**：剩下的图按文档顺序重新编号、节号保持连续（删掉一节不留空号）。
5. **账本**：在 `series.json` 的 `meta.skipped` 记 `{"fig": "fig10", "missing": "<缺的来源>", "rq": "<CQ>"}`；被跳过的图本季不追加新点，历史原样保留给下季。`selfcheck.py` / `docxcheck.py` 的图数按「全套减去 meta.skipped」核对。
6. **交付说明里列出**：缺了哪些来源、因此删了哪些图和小节（无人值守的运行写进它要求的 "Notes for the reviewer"）。
7. **什么都不剩才停**：当季 10-Q（Q1 用 10-K）都没有，OTF 本身没东西可写 —— 说清缺什么，停下。

| 缺的来源 | 本季删掉 |
|---|---|
| `OTF\` 当季 10-Q / 10-K | 无法成稿（见第 7 条） |
| `OTF\` 当季 earnings deck | 只靠 deck 的数与点评；10-Q 能给的照常 |
| `OTF\历史报告\` 某一期 | 需要那一期的历史点：该点不画；整条序列缺到画不出 → 删该图 |
| `competitor earnings\` 某一家 | 图 10–14 与 T9 里该家的那一列 / 那条线 |
| `competitor earnings\` 全部 | 2.6 BDC competitor analysis 整节（图 10–14、T9） |
| `行业\1 - Broker public BDCs sentiment\`（MS Tracker / JPM） | 图 15–20 及 3.3 中靠它们的点评；T10 里对应券商列 |
| `行业\1 - Broker Software+AI\` | 图 21、T11 及 4.3 中靠研报的部分 |
| 联网行情 | 图 8–9、T8（2.5 Price comparison） |
| `<YYYYMM>OTF 草稿*.xlsx` | 图 1 点评里的 AI-impact 分级那句 |

## 从附件运行（Claude API、AID 研究面板的「AI 生成」）

拿不到 `04 Research\Software\` 文件夹和 `_charts\` 账本时（源文件是随请求附上或传进容器的，研究面板的 AI 生成就是这样）：

- 每个附件按**内容**识别（首页、标题、报告期、sheet 名），对照 §1.1 的来源表；文件名可能被改短，压缩包已解开。不在附件里的来源按上面「缺料」处理。
- 没有账本历史：每张图只用附件本身的数据（10-Q / deck 自带上期列，历史 10-Q 若附上就用）；需要附件里没有的历史 → 按缺料跳过。
- 本 skill 自带的 `scripts/` 照常可用；依赖文件夹或账本的检查改为手工做到同样标准（每个数可追到附件或带出处的网页、图在插入宽度下可读不重叠、编号 1..N 连续、EN/CN 数字一致），不因 `_charts\` 不存在而停。
- 不往任何文件夹回写；文档按运行指令给的位置和文件名产出（如 `/tmp/outputs/`）。
- 「门」按运行指令处理：指令说没有人值守时，自己核图核数后继续，把本来要问的写进指令要求的说明里。

## 用户说「不用重新取数」时怎么办

改了样式或版面之后不需要重跑取数 —— 取数是阶段一 3–5 小时里的绝大部分，
而出图只读 `series.json` 和 `prices.csv`，不读 PDF、不联网，几十秒的事。

所以用户说「不用重新取数」「直接用账本里的数」「阶段一跳过」这类话时，**照做**：
从 `series.json` 重出全部 PNG，然后照常过门、写正文。**不要犟着从头再跑一遍取数。**

先确认三件事，任一条不满足就说清楚、别硬跑：

- `CQ` 没变（最新 filing 还是同一期）。变了就是新季度，得重新取数。
- `series.json` 里没有 `_VOID` 标记、没有该有值却是 `null` 的。跑 `review_sheet.py` 看有没有 ✗。
- `prices.csv` 覆盖到位（基准日各 ticker 齐备、无大段空值）。

然后这三件事**不许省**，都是这种情况下最容易被偷掉的：

1. **`build_charts.py` 必须按当前的 `03_style.md` / `00_layout.md` 重新生成，不许复用上次那份。**
   版面规则改了而生图脚本没改，等于什么都没改 —— 这是唯一的真实风险。
2. **不许复用 `out/` 里的旧 PNG。** 判据是画布宽：旧图画布 7.7–19.9 in，
   插到 6.05 in 之后图内脚注只剩 2.3–5.9 pt。`chartlib.save()` 的版面锁会拦，别用 `skip_check` 绕。
3. **PNG 变了签收就失效**，不许拿旧的 `APPROVED_<CQ>.json` 蒙过去。
   `approve.py --check` 会因为 sha256 变了而拒绝 —— 这是对的，重新出清单、重新让用户签。

反过来，如果用户说「图不用动，只改正文」，先跑 `approve.py --check`：
`CQ`、`series.json`、每张 PNG 的 sha256 三项全对才能直接进阶段二，否则就得重出图重新签。

## 三条贯穿全程的铁律

**一、样式冻结、数据只追加。**

```
图 = chartlib.py（样式，一次写死永不改） × series.json 的窗口切片（数据，只追加）
```

账本放 `04 Research\Software\_charts\`，**跨季共用，不放进每季的 Report 文件夹** —— 放那儿每季都得手动复制，忘了就等于丢账本，丢了要 3–5 小时重建。当季 Report 下只建 `_charts_snapshot\` 放当季 PNG 和账本快照做留痕。

**〇、T3 软件分层的四个占比必须从本季 10-Q 的 Schedule of Investments 逐家公允值自算。**
`202607OTF 草稿 xlsx` 的 `Crosscheck` sheet 是**去年的持仓与口径**，不许当占比来源 —— 组合每季都在变（本季 205 家 / $14.7bn vs 上季 203 家 / $14.1bn），照抄就是把一年前的结构冒充本季。公司→分层映射冻结在 `_state/layer_map.json`，每季只判名单差异。`selfcheck.py` 有针对 `tbl03` 的专项检查，`src` 里出现 `.xlsx`／`草稿`／`Crosscheck` 直接 fail。细节见 `08_tables.md` 的 T3 专节。

**〇之二、出图后必须自己逐张看过。** `guards.check()` 是 bbox 级的硬拦，但「两个标签贴得太近」「数字压在折线上」「图例盖住末点」它抓不到。**看到文字重叠就重做那张图，不许交出去让用户发现。**

**二、正文里凡图表上出现过的数，一律从 `series.json` 读，禁止为写正文再抽一遍。** 否则 NAV 图写 16.48、正文写 16.49，两处各自自洽，通读发现不了。出稿后 `crosscheck.py` 扫全文数字回账本核。

**三、上一版报告只能用来对答案，绝不能当数据源** —— 连「先填占位以后再核」都不许。实测过：v1 报告 T1 的 `Memo: senior secured debt` 本身就是错的（81.5% 应为 81.2%），抄它等于把错冻进账本。

## 阶段一 · 出图（`references/01`–`09`）

1. 跑 `scripts/setup_font.sh` 装 Lato 并清 matplotlib 缓存。**跳过这步整套图字形就走形。**
2. 扫 `OTF\` 下所有 PDF 首页读 `For the quarterly period ended <date>`，取最新那份定出 `CQ`；`PQ` = 前一季；`AS_OF` = 运行日前一交易日。→ `01_inputs.md`、`02_quarter_window.md`
3. **只抽当季那一期**，追加进 `series.json`，每点写 `src`（**两层写法**：图级写清哪一期出自哪份文件，点级只补差异，没差异写 `same`；`src` 只写来源不写评论）。**历史点一个都不许动。**
4. `prices.csv` 只补 `上次末日 + 1 → AS_OF`，按 `date` 去重。
5. **B 类标题（图 15/16/17/18/20）的判断句按新数据重算**，跑 `titlecheck.verify()`。→ `03_style.md`
6. 跑 `build_charts.py` + `build_tbl01.py`。`save()` 自动跑 `guards.check()` 四道硬检查：全英文、**文字不许压叠**、**数值标签必须水平**、**描点直径 = 线宽 × 2**。**不许用 `skip_check=True` 绕过。**
7. ⭐ **自己逐张打开 `out/` 里的 PNG 看一遍。** `guards` 只能抓 bbox 重叠，抓不到「贴太近读不清」「标签压到线上」「图例盖住数据」这类。**看到任何文字重叠或压到坐标轴，就把那张图重做** —— 调 `xytext` 偏移、隔点标注、抬 y 轴上限、图例挪到图外，改完再看。这一步不做等于把废图交给用户。
8. 跑 `selfcheck.py`（§12 清单的代码版 + 来源可追溯性），跑 `review_sheet.py` 生成核对清单。**恒等式不通过不许进门。**

### 首次搭建（账本不存在，3–5 小时）

**别一口气全量。** 先拿**图 5 和图 10** 试跑（一个测本地 PDF 抽数、一个测联网抓竞品历史），跟上一版报告逐个数字对；对上了再开全量。回填只做数不出图，填完**立刻把 `series.json` 备份到季度文件夹外面**。详见 `02_quarter_window.md`。

## 门 · 停下等签收（`references/10_gate.md`）

把两样东西交给用户：**`out/` 里的 22 张 PNG** + **`out/REVIEW_<CQ>.md` 核对清单**（算术恒等式结果 + 本季新增每个数一行：图表/系列/上季/本季/QoQ/出处）。

明确说「请逐张看图、逐行核数，确认后我再写正文」，**然后停下**。

用户确认后 `python3 approve.py --sign`。阶段二启动前必须 `python3 approve.py --check`。

> **没有有效签收，阶段二拒绝启动。** 不许用默认值、不许「先写着等下再核」。**定时任务或无人值守场景下也必须停在门口。** 门后改过任何图或数，签收自动失效，要重新交付清单再签。
>
> **门可以跨会话** —— 签收文件落在磁盘上，所以阶段二可以是全新一次会话。这也顺带解决上下文问题：生图和写三万字正文本来就不该挤在一个会话里。

## 阶段二 · 正文（`references/00`、`08`、`11`、`12`）

1. `approve.py --check` 通过才开工。
2. 跑 `conclusions_diff.py _state/conclusions_<PQ>.json`（首季没有上季快照就从上一版报告倒推一份），把输出当作各处 `QoQ Chg` 的输入。
3. 按 **v1 最终版**的章节顺序写（`00_layout.md`）；行文规格照 V4（密度、口吻、禁用词、环比记法）。
3. 逐节按 `11_prose.md` 的来源表取数：标 **L** 的从账本读，标 **N** 的从当季 filings/研报抽，标 **W** 的联网，标 **H** 的留空。
4. 13 张 Word 表按 `08_tables.md` 的**真实样式**（有框线 `#C9D2DC`、表头 `#1F3B5B` 白字、首列 `#EEF2F6`）；T1 用现成 PNG。表头跨页重复。
5. **页面 A4 竖版**（仅 2.6.1 那一节横版，靠分节实现）；**正文 Calibri Light 小四、纯黑 `#000000`**；**所有表格 Arial 8 号**。**文件名与首页大标题、页眉用报告季度 `RQ`（撰写时间，如 2026Q3），文档内部的数据时间一律用 `CQ`/`PQ`（季报时间，如 Q2'26）——两者差一季，不许混。****Summary 与 1. News 之间硬分页，News 另起一页。**插图用 `out/` 里的 PNG，宽度 == **6.05 in = 正文宽度的 85%，居中**（画布 `figsize[0]` 也是 6.05，1:1）；**唯一例外是封面顶部长横条 —— 7.11 in，与正文两端同宽**，**不另加题注**（标题已烧在图里）。图 1 是一张 PNG 内含左右两个饼。**阶段一 21 张图画布一律 6.05 in（正文宽的 85%），不为并排重出；阶段二有 10 张缩到 3.50 in 并排 —— 2.6.2 的图 10‖11、2.6.3 的图 13‖14、**3.3 的图 15‖16 / 17‖18 / 19‖20（三组，每组下面一段合并分析）**，两图之间不插文字，说明与分析合并成一段放在两图下方。其余（含同节的图 12、图 21）6.05 in 居中。****News 每条来源必须是超链接且指向该篇文章的完整 URL，裸域名不算；拿不到准确 URL 就删掉这条。****2.7 不要 Valuation，也不许写 `[To be written]` 之类占位 —— Things we should know 写不出来就整节删掉。**详见 `00_layout.md`。
6. 出 docx 后跑 `python3 crosscheck.py REPORT.docx` —— **可疑矛盾改到零**，账本外的数逐个确认出处。
7. 再跑 `python3 docxcheck.py REPORT.docx` —— **✗ 必须为 0**。它查的是 v3 实测基准：A4 竖版 + 唯一横版节、
   边距 830/832、正文 Calibri Light 12pt（**不许残留 run 级 Arial 覆盖**）、正文纯黑 `#000000`、图片画布 6.05 in、单图插入宽 6.05 in（封面横条 7.11 in 恰 1 张；并排 3.50 in 恰 10 张，多一张少一张都报错）、
   表头带 `w:tblHeader`、表格 Arial 8pt、文件名与页眉季度一致、Summary 后有分页、来源链接不是裸域名、没有 `To be written` 占位。
7. 落 `_state/conclusions_<CQ>.json` 结论快照，跑 `conclusions_check.py --strict` 过关。
9. 按 `12_checklist.md` 的阶段二部分逐条自检。

> **写正文之前先跑 `conclusions_diff.py`** 对比上季与本季快照 —— 它是各处 `QoQ Chg` 的输入，不是事后检查。数字冻在 `series.json`，结论冻在快照里；两样都不靠记忆。

**建议每写完一块正文交用户看一次**，不要四块写完一起看。图的错是算术错、程序能兜；正文的错是判断错，只有人能看出来，而且一块写错会污染 Summary 和后面几块的回指。

## 脚本

| 文件 | 用途 |
|---|---|
| `setup_font.sh` | 装 Lato + 清字体缓存。**每次新环境第一步** |
| `chartlib.py` | 样式冻结层。`save()` 自动调 `guards.check()`。**定稿后不许改** |
| `guards.py` | 图内全英文（CJK）+ 文字不许压叠。已在 21 张图上标定阈值 |
| `titlecheck.py` | B 类标题的判断句与数据核对，矛盾就 raise |
| `test_titles.py` | titlecheck 标定用例：本季 5 张全过，六种「照抄上季但数据已反」全部拦下 |
| `tablelib.py` / `build_tbl01.py` | 表格出图层（HTML+CSS → Chromium 截图），出 T1 |
| `review_sheet.py` | 门的核对清单 + 算术恒等式自查（`--strict` 不过就退出）|
| `approve.py` | 签收闸门：`--sign` 落签收，`--check` 校验 |
| `selfcheck.py` | 自检清单的代码版，含来源可追溯性（图级 + 点级两层规则）|
| `crosscheck.py` | 扫最终 docx 每个数字回账本核，抓「近似但不相等」的图文矛盾 |
| `docxcheck.py` | 成稿版面自查：分节纸张/边距、正文字体字号、图片插入宽、画布 1:1、表头跨页。基准取自 v3 实测 |

## 十三条不许犯的错

1. **季度不许写死。** 所有标题、轴标签、脚注、正文里的季度字样都从 `CQ` / `PQ` 推导。
2. **没有有效签收不许写正文。** 无人值守也必须停在门口。
3. **正文的数从账本读，不许重抽。** 出稿后 `crosscheck.py` 可疑矛盾改到零。
4. **上一版报告只能对答案，不能当数据源**，连临时占位都不许。
5. **§2.3 的图 5 / 图 6 图面不出现来源、不出现括号。** 括号连内容整段删掉。
6. **图 15–19 永不套两年上限**，`window_max` 一律 `null`，左端一期都不裁。
7. **图 21 每季重画。** 券商名单和分层方式每季都变，四层不是固定框架。
8. **B 类标题每季重算判断句**，必过 `titlecheck.verify()`；不许删掉判断句降级成固定标题来绕过检查。
9. **21 张图画布一律 6.05 in = 正文宽的 85%（单图时 1:1，居中，不顶两端；封面横条 7.11 in 例外）**。**折线描点直径 = 线宽 × 2**（`ms=chartlib.ms(lw)`）；**图内数值标签一律水平**，条形图上的数值尤其不许竖排。**出图后自己先逐张看一遍有没有文字重叠 —— 有就重做那张图**，`guards` 拦不住的要人眼补，不许 `skip_check` 绕过。，图内字号按 `00_layout.md` 新表重定（标题 13pt / 脚注 7.5pt）。不许再用 13–18 in 的旧画布 —— 那是对着 V1 的像素数复刻的，插到 A4 上脚注只有 2.2–7.8pt（v3 实测，并排的图 10/11 只剩 2.2pt）。**21 张图纯白底、Lato、只有一套色板。** 除 OTF（`#A93226`）外不许有第二个红色系；同一个 ticker 全篇同色。
10. **图内不许有文字压叠**，`guards.check()` 报错就修布局，不许 `skip_check=True`。
11. **研报里的图一律读点重画，不许截屏**；正文插图只用 `out/` 里的 PNG。
12. **全篇英文；broker 表不写研究员姓名；尽量不用括号（2.6.1 全段禁用）；提到回购注明公司。** y 轴用账本冻结的 `ylim`/`ytick` 禁 autoscale；脚注 `$` 写成 `\$`。
13. **结论快照不许记粗。** 按对象存字段，不许按节存摘要 —— 「立场转向 stabilization」这种粒度写不出驱动，环比就失去意义。券商每条 key point 必带数字，`open_items` 的 `watch_next` 下季必须逐条回答。`conclusions_check.py --strict` 过不了就是记粗了。
