## 逐节

### Summary

无新数据。从三大块成稿里各挑最重要的 **3 个本季变化**提炼，每块恰好 3 条 bullet，每条一句话带一个关键数字（数从 L 读）。**不得引入正文没有的内容。** 不写累计/静态数（「上市以来跌 X%」这类不进 Summary）。生僻词加脚注解释。**最后写**。

### 1. News

| 小节 | 来源 | 要点 |
|---|---|---|
| 1.1 Blue Owl & OTF | **W** + `行业\OTF & BlueOwl NEWS.docx` | **必联网**，范围 = 上季 + 本季到**运行日前一天**。诉讼/监管/集体诉讼必搜。按重要性排序不按时间，最重磅一条放最前可加粗。每条 = 事件 + 日期/来源简称 + 关键数字 + 一句对 OTF 的含义。区分「事件」vs「观点」，单一来源标「待核」。**每条末尾附来源链接。** 查到重大利空必须放 |
| 1.2 Private credit | **W** + `行业\2 - private credit news\` | 只留暴雷/违约/赎回/诉讼/发起人托底/板块承压；排除财报与股价噪音 |
| 1.3 AI related | `行业\2 - Website - News\`（含 Bain 子目录）| 5–7 条，一条一个核心进展，写它**如何颠覆/影响软件行业**而非复述标题；专业新闻人口吻。剔除股价/估值类噪音（「某股被低估」「抛售过度」）。不写来源公司前缀、不写日期页码 |

> **保鲜期**：1.1 / 1.2 必须到运行日前一天。若门到出稿隔了一天以上，**出稿前重跑这两节**。

#### News 的来源必须是真超链接，且指向那一篇的准确网址

三个小节**每一条新闻**结尾都要挂来源，规则写死：

1. **必须是 Word 超链接**（`<w:hyperlink r:id="...">` + `document.xml.rels` 里 `TargetMode="External"`），
   不是纯文本，不是「Source: bain.com」这种裸域名。
2. **链接目标必须是那篇文章自己的完整 URL**，带路径 —— 例如
   `https://www.bain.com/insights/the-100-billion-saas-opportunity-hiding-in-cross-system-labor/`。
   **只给 `bain.com` / `bloomberg.com` / `hbr.org` 这种域名级链接一律算错**，读者点进去落到首页找不到原文。
3. 可见文字可以短（出版方名或域名都行），但**目标 URL 必须完整**。
4. **拿不到准确 URL 的新闻就不要写这一条。** 素材是本地 docx、原文网址已经丢了的，
   联网把原文找回来再写；找不回来就删掉这一条，不许用域名凑。这条和数据纪律同级 —— 缺料不臆造。

# 结论快照：让「观点环比」和数字一样可核

## 为什么要有

数字冻在 `series.json` 里，**结论没有任何东西冻**。报告里每一处 `QoQ Chg`、「较上季」、「排序变化」，靠的都是模型通读上季那份三万字 docx 之后的记忆 —— 不可核，而且每季都要重读一遍。

解法与账本同源：每季写完落一份 `_state/conclusions_<CQ>.json`，下季读它。

## 铁律：按对象存字段，不许按节存摘要

**「每节写一两句摘要」是错的做法。** 那种粒度只够写「立场转向 stabilization」，写不出「因为对非应计见顶的判断变了」—— 环比就失去了驱动，效果甚微。

**判断标准**：报告里每一处要写环比的地方，把它需要的**输入字段**全存下来，一个不省。摘要会丢信息，字段不会。

## 字段定义

```jsonc
{
  "cq": "Q2'26",

  "brokers": [{                         // 当季实际收到报告的每一家，一家一条
    "name": "BofA",
    "coverage": "OTF",                  // OTF / BDC / Private Credit / Software+AI
    "covers_otf": true,                 // true 时 rating/target_price/action_date 必填（T7 要拿它比）
    "rating": "Neutral — maintained",
    "target_price": "$11.50",
    "valuation_basis": "~0.7x NAV",
    "action_date": "2026-08-06",
    "view_label": "Stable quarter, credit pristine, profitability to lag",
    "stance_driver": "较上季由 yield-pressure caution 转向 stabilization：NAV 由 −4.9% 转为持平 16.48，组合收益率 +10bp 至 9.3%",
    "key_points": ["…", "…", "…"]       // 3–4 条，**每条必带具体数字**
  }],

  "companies": [{ "ticker": "MSFT", "view_label": "…",
                  "key_metric": "AI ARR 超过 $37bn，同比 +123%",
                  "key_points": ["…", "…"] }],

  "theses": {
    "peer_thesis": "2.6.1 那句粗体核心判断的原文",
    "consensus": ["…"],                 // 3.2 市场共识，4–5 条原文
    "debates": [{ "topic": "…", "side_a": "…", "side_b": "…", "core": "…" }],   // 1–2 个
    "layer_ranking": ["Application（最受压）", "…", "Infrastructure（受益且最具防御性）"]
  },

  "open_items": [{                      // 2.7 / 3.4 / 4.2 的每个议题 —— 下季的作业
    "section": "2.7", "topic": "…",
    "transmission": "对 OTF 的传导路径",
    "watch_next": "下季要盯什么"         // 下季正文必须逐条回答
  }],

  "section_notes": { "2.1": "…", "2.2": "…" }   // 只有这一层才是「一句话」的粒度
}
```

## 颗粒度检查（写完必跑）

```bash
python3 conclusions_check.py _state/conclusions_<CQ>.json --strict
```

拦这些：占位词（`同上` / `略` / `无变化` / `TBD`）、模糊表述（`整体承压` / `有所改善` / `等等` / `若干`）、太短（key point < 15 字符）、**券商 key point 不带任何数字**、条数不够（券商 <3 条、共识 <4 条、分歧 0 个或 >2 个、分层排序 <3 层）、`covers_otf` 却缺 rating/target_price/action_date、`open_items` 没写回哪一节。

**实测**：一份写粗的快照会被拦下 27 项并逐条点名。检查不过就是记粗了，回去补，不许放行。

## 下季怎么用

```bash
python3 conclusions_diff.py _state/conclusions_<PQ>.json _state/conclusions_<CQ>.json
```

输出四块，直接喂给对应的 `QoQ Chg` 格子：

1. **券商逐家** —— rating / 目标价 / 估值基准 / 立场标签哪个变了，key_points 的进出（新增判断、上季有本季未再提）
2. **公司逐家** —— view 标签与关键指标的变化
3. **theses** —— 核心判断、共识条目进出、分歧的更替、分层排序有没有动
4. **open_items 闭环** —— 上季每个议题的 `watch_next` 逐条列出，**本季正文必须回答**，答完才决定收口还是继续留

两处 diff 会主动提醒的情况：

- **某家券商本季没出报告** → T7/T10 的 `QoQ Chg` 写「本季无更新，沿用上季」，**不许凭空延续它的观点**。
- **上季某个分歧本季不再列** → 是收敛了还是被更大的分歧顶掉了？**正文要交代**，不能悄悄消失。

## 顺序

`conclusions_diff.py` 的输出要在**写正文之前**读 —— 它是写 `QoQ Chg` 的输入，不是事后检查。

快照本身在**正文写完后**落盘，跑 `conclusions_check.py --strict` 过关才算这一季完成。

**快照优先、上季报告兜底**：上季那份 docx 仍留在季度文件夹里。快照没覆盖到的情况（比如临时加了一节）回去翻报告。
