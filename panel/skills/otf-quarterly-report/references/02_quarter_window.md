# 季度解析 · 冻结历史 · 滚动窗口

### 2. 季度解析（**最关键，每季必重算**）


### 2.1 定义

| 记号 | 含义 | 怎么定 |
|---|---|---|
| **`RQ`** | **报告季度 = 撰写这份报告的时间** | **从运行日的日历季度来**，不是从 filings 来。2026 年 8 月跑 → `RQ = 2026Q3` |
| `CQ` | 数据本季 | `OTF\` 里最新一期 10-Q（或 10-K）封面的报告期末日所属日历季度 |
| `PQ` | 数据上季 | CQ 往前推一个日历季度 |
| `AS_OF` | 股价截止日 | 运行日的**前一交易日**（跳周末与美股假日） |

### 2.1.1 ⛔ `RQ` 与 `CQ` 是两个不同的季度，不许混用

季报总是滞后一个季度：2026 年 8 月能拿到的最新 10-Q 是 6/30 期末，也就是 `CQ = 2026Q2`，
但这份报告是 **2026Q3 写的**，所以 `RQ = 2026Q3`。v3 就是这样：页眉写 `2026Q3`，图上写 `1Q25 – 2Q26`。

| 用 `RQ` 的地方 | 用 `CQ` / `PQ` 的地方 |
|---|---|
| **文件名**：`OTF_<RQ>_OTF update_v<n>.docx` | 正文里所有数字、所有 QoQ 对比 |
| **首页大标题**里的季度 | 所有图的标题、轴标签、图例、脚注 |
| **页眉右侧**的季度 | 所有表的「上季 / 本季」列头 |
| — | `series.json` 的期次 key、`APPROVED_<CQ>.json`、`REVIEW_<CQ>.md` |

**判据：文档内部凡是描述数据的时间一律 `CQ`/`PQ`，一个字都不改；只有文件名、首页大标题、页眉这三处用 `RQ`。**
写成 `OTF_2026Q2_...` 或首页标题写 `2026Q2` 都是错的。

**严禁把 `2026Q1 / 2026Q2` 写死。** 报告里出现的 `Q1'26 vs Q2'26` 只是 2026Q2 那一季的取值；下一季自动变成 `Q2'26 vs Q3'26`。所有图标题、轴标签、图例、脚注里的季度字样都必须由 `CQ`/`PQ` 推导。

### 2.4 行业图（15–20）的期数陷阱

MS Private Credit Tracker / JPM 报告**比 OTF filings 晚一季**。以 2026Q2 那一季为例，Tracker 是 1Q26 版，所以图 15–20 的最新点是 `Q1'26`，而图 1–7 的最新点是 `Q2'26`。

**规则**：行业图的最新点 = 文件夹里那份研报自己的最新期，**不要为了跟 OTF 对齐而外推一期**。同时在正文/脚注里写明「行业口径截至 <研报期>，尚无 <CQ> 数」。

### 2.5 上季数不从当季 10-Q 的对比列取

10-Q 的对比列常常是**上一年年末**而不是上一季，且会按新口径重述。**上季数一律从上季那份 filing 自己取。** 图 1 的行业分布尤其容易踩这个坑。

### 3. 冻结历史 + 滚动窗口（**样式一模一样，只在右侧续画**）


### 3.1 要解决的两个痛点

1. **样式要跟第一版一模一样** —— 每季重写画图代码，颜色、字号、标签位置就会慢慢漂。
2. **序列不能无限变长** —— 再画八个季度，图 5 / 图 10 就会横向拉成一条细带，读不出东西。

解法是把**样式**和**数据**彻底分开，各自冻结：

```
图 = chartlib.py（样式，一次写死永不改）  ×  series.json 的最后 N 期（数据，只追加）
```

样式层不动 → 输出与上一季**像素级同款**；数据层只在右端追加一期、左端滚出一期 → 图**永远一样宽**。

### 3.2 目录结构

**位置：放在 `Software\` 这一层，跨季共用，不放进每季的 Report 文件夹。**

```
04 Research\Software\_charts\          ← 账本本体，只有一份，永不复制
├─ chartlib.py        样式层：色板 / 字体 / 标题 / 数据标签 / 脚注 / 双轴 / 右侧标签 / 窗口切片
├─ guards.py          出图前硬检查：图内全英文 + 文字不许压叠
├─ titlecheck.py      B 类标题的判断句与数据核对（§4.4）
├─ tablelib.py        表格出图层（T1）
├─ series.json        数据层：全历史点 + 每点出处（只追加）★ 最重要，另存备份
├─ prices.csv         股价日线缓存（只追加，按 date 去重）
├─ build_charts.py    读 series.json + chartlib → 出 21 张 PNG
├─ build_tbl01.py     出 T1 的 PNG
├─ selfcheck.py       §8 清单的代码版，含来源可追溯性检查
└─ out\               当季 PNG

<季度> - Software\Report\_charts_snapshot\   ← 每季只留留痕，不是账本
├─ series_<CQ>.json   当季跑完时的 series.json 快照
└─ out\               当季 21 张图 + T1 的 PNG
```

**为什么不放每季的 Report 下面**：放那儿每季都要手动复制一份 `_charts\`，忘了复制就等于丢账本，而丢了要 3–5 小时重建。放 Software 层就没有复制这一步，账本永远只有一份。

每季只做两件事：往 `series.json` 追加当季数据、重跑 `build_charts.py`。**不要从零重写画图代码。**

首次运行（`_charts\` 不存在）才需要按 §4 / §6 从头搭一次，并把 2026Q2 版报告里已有的历史点**逐个回填**进 `series.json`。

### 3.3 series.json 结构

```json
{
  "meta": { "cq": "Q2'26", "pq": "Q1'26", "as_of": "2026-08-14", "updated": "2026-08-17" },
  "charts": {
    "fig05_pik_share": {
      "window": 6,
      "series": {
        "OTF": {
          "Q1'25": { "v": 15.3, "src": "历史报告/0001747777-25-000015.pdf p.F-4；PIK int+div ÷ TII" },
          "FY25":  { "v": 14.0, "src": "历史报告/0001747777-26-000012.pdf（10-K 全年 − 前九个月）" },
          "Q1'26": { "v": 13.1, "src": "2 - OTF 10-Q季报 2026Q1.pdf p.F-5" },
          "Q2'26": { "v": 12.5, "src": "OTF Q2.pdf p.F-5；$42.3mm ÷ $338.0mm" }
        },
        "BDC_SECTOR_AVG": {
          "Q1'25": { "v": 6.6, "src": "MS PCT 1Q26 chart", "est": true },
          "Q1'26": { "v": 6.4, "src": "MS PCT 1Q26 正文披露值" }
        }
      }
    }
  }
}
```

每个点三件事：值 `v`、出处 `src`、`est: true`（表示从研报图上读点而非披露值）。

**`src` 写成什么样 —— 这里容易搞反：**

`src` 是**回执，不是路标**。它记的是「这个已经冻结的数当初从哪儿来的」，不是「下季去哪儿找」。这个区别决定了该写什么：

| 必写 | 可选 | 不要指望它 |
|---|---|---|
| **文件名**（`OTF Q2.pdf` / `0001747777-25-000015.pdf`）| 页码 / 幻灯片号 | 拿页码当下季的定位依据 |
| **文内锚点**：表名或段落首句（`Investment Rating 表` / `"our portfolio consisted of" 段`）| 算式（`$42.3mm ÷ $338.0mm`）| |

**为什么页码只是可选**：10-Q 每季页码都会挪、deck 幻灯片顺序会变、broker 研报连标题都可能换。**下季定位一律用宽松文本锚点重新找**（§1.2），绝不能照着上季的页码去翻。页码的唯一价值是让人复核当初那个数时少翻几页 —— 而它指向的那份文件已经归档、永不变化，所以写了就永远有效。

**两层写法 —— 别在每个点上重复同一句话：**

```json
"fig07_risk_rating": {
  "src": "Q1'25 出自 历史报告/0001747777-25-000015.pdf 的 rating 表；Q2'25–Q1'26 出自 3 - Q1'26 OTF Earnings Presentation p.13；Q2'26 出自 Q2'26 OTF Earnings Presentation",
  "series": { "R1": { "Q1'25": {"v": 7.9, "src": "same"}, ... } }
}
```

- **图级 `src`**：这张图哪一期出自哪份文件，一次写清，兜住全部点。
- **点级 `src`**：只补**差异** —— 算式（`$42,286k ÷ $338,032k`）、口径例外（`= unsecured 3.2% + specialty finance debt 0.3%`）、或推导来源（`八档相加`）。没有差异就写 `same`。
- **判定合格的下限**：这个点自己的 `src` 能解析，**或者**它所在的图有可解析的图级 `src`。两者都没有才算不合格。

`selfcheck.py` 按这个两层规则检查。可解析的特征包括：本地 `.pdf` 文件名、SEC accession 号、`10-Q` / `10-K` / `8-K`、`Note <n>` / `MD&A` / `financial highlights`、`earnings release` / `earnings presentation` / `investor presentation` / `press release`、`Tracker` / `Figure <n>` / `slide <n>` / `p.<n>`、ticker（联网取的竞品材料本地没有文件名，靠 ticker + 文件类型 + 附注号定位）。

**`src` 里只写来源，不写评论。** 订正理由、口径争议、跟上一版的差异都放到同一行的 `note` 字段 —— 否则「上一版报告此行写 81.5%」这种说明会被禁二手数据的检查误判成「这个数抄自上一版报告」。

### 3.4 铁律：历史点只读

| 动作 | 允许吗 |
|---|---|
| 给已有系列**追加**当季那一个 key | ✅ 每季就做这个 |
| 修改已有期的 `v` | ❌ 除非走 §3.4 的重述流程 |
| 重新从旧 filing 抽历史数 | ❌ 绝对不要 |
| 删掉超出 window 的历史点 | ❌ 留着做审计和长期均值 |

**为什么**：同一份 PDF 让模型读两次，抽出来的行数和数字会漂（这次 39 行、下次 32 行，而且不会报错）。历史一旦冻结，漂移只可能出现在当季那一列，肉眼一眼能看出来。

**确实发现历史点错了**，不许静默改，走重述流程：

```json
"Q3'25": { "v": 13.8, "revised_from": 13.5,
           "revision_note": "上季误用 YTD 口径，改为单季", "revised_in": "Q2'26" }
```

并在该图脚注加一行 `<period> restated in {CQ}; prior print was <旧值>`。

### 3.5 滚动窗口：先只往右加，满两年才开始裁左端

**规则改了，按这条来：** 出现新一季数据时**只在右端追加，不删左端**，让图自然变长 —— 一直加到图上的季度点数**满 8 期（两年）**为止。第 9 期出现时，才从左端滚出最早一期，此后始终保持最多 8 期。

> 例：最早是 `Q1'25`。`Q2'25 … Q4'26` 一路只加不删，到 `Q4'26` 正好 8 期两年。`Q1'27` 出来时才删掉 `Q1'25`，图上变成 `Q2'25 … Q1'27`，仍是 8 期。

`window_max = 8` 写在 `series.json` 里，出图时取 `periods[-window_max:]`；不足 8 期就把有的都画出来。更早的点永远留在文件里做审计与长期均值，只是不上图。

```json
"fig05_pik_share": { "window_max": 8, "ylim": [4, 18], "ytick": 2, "series": { ... } }
```

2. **脚注里的 `{首期}–{末期}`**；
3. **Word 正文点评里的相对表述** —— 「五个季度以来」「from its 1Q25 level」「since listing」这类参照期跟着窗口滚。窗口滚了但正文还写 1Q25，就是硬伤。

### 3.5.1 y 轴要「粘住」，不许每季 autoscale

这是滚动窗口最隐蔽的坑：窗口一滚，最大值/最小值就变了，autoscale 会把 y 轴上下界跟着改，于是同一张图这季顶到 18、下季顶到 16 —— 曲线形状看着完全不同，读者会以为数据变了。**实测过，确实会发生。**

规则：**把 y 轴上下界和刻度步长存进 `series.json`，当成样式的一部分冻结。**

```json
"fig05_pik_share": {
  "window": 6,
  "ylim":  [4, 18],
  "ytick": 2,
  "series": { ... }
}
```

- 每季出图**直接用 `ylim` / `ytick`**（`ax.set_ylim(*ylim)` + `MultipleLocator(ytick)`），**不调 autoscale**。
- 只有当季新点**真的越界**才扩：向外扩到下一个 `ytick` 整数倍，写回 `series.json`，并在自检清单里记一笔「图 X 的 ylim 从 A 改到 B，因为 <原因>」。
- **只扩不缩。** 窗口滚掉一个高点不构成收窄理由 —— 收窄了跨季就对不上。
- 首次设定时：取历史全量数据的 min/max，各留 8–12% 余量，再向外取整到刻度步长（占比类 0.5pp、倍数类 0.5x、每股 0.2 美元、指数化价格 10）。留足余量，以后就少改。

### 3.6 股价图（图 8 / 9）的例外

「上市以来」是这套报告的论点之一（跌幅表就是按上市日算的），所以起点**默认锚在 2025-06-12 不滚动**。但要防止 n 个季度后横轴挤成一团：

| 跨度 | 画法 |
|---|---|
| ≤ 24 个月 | 保持上市日 2025-06-12 归一至 100（现状；到 2027-06 之前都是这一档） |
| > 24 个月 | 改画**最近 24 个月**，窗口起点当日归一至 100；标题加 `— last 24 months`；脚注写 `rebased to 100 at <起点>; since-listing performance in the table below` |

两年上限与 §3.5 一致 —— 季度图 8 期两年，日线图 24 个月两年。

- **跌幅表永远按上市日算全程**，不受窗口影响。
- x 轴主刻度密度按跨度自动：≤18 个月按月、18–24 个月按季。
- `prices.csv` **只追加不重抓**：每季只补 `上次末日 + 1 → AS_OF`，按 `date` 去重后排序。**历史价格永不重下** —— 数据源的复权口径一变，旧图形状就会跟着变，跨季就对不上了。

### 3.7 chartlib.py 必须封装的样式冻结点

写一次、以后只调用，**不许在单图脚本里重复设样式**：

| 函数 | 冻结什么 |
|---|---|
| `PALETTE_A` / `TICKER_COLORS` | §4.2 / §4.3 的色号常量，逐字照抄。**只有一套色系** |
| `use_style()` | Lato、纯白底、网格 `#E3E7EC`、spine、`unicode_minus` |
| `title(ax, text, loc)` | 字号、bold、色 `#16283F`；图 10–14 传 `loc='left'` |
| `subtitle(ax, text)` | 图 10–14 的口径 + Source 行，色 `#5A6B7B` |
| `footnote(fig, text)` | 左下、`#5A6B7B`、**按画布宽度自动折行并顶到右边缘** |
| `bar_labels()` / `line_labels()` | 小数位、bold、颜色随系列 |
| `highlight_last(ax, x, y)` | 本季点 `#A93226` 大圆点 + 同色标签 |
| `right_axis(ax2, color)` | 右轴轴脊 / 刻度 / 轴标题同色 |
| `right_edge_labels()` | 图 10–14 的「虚线 → ticker 粗体 → 数值列」三段式 + 防重叠错开 |
| `stacked_labels()` | 堆叠柱段内白字 bold、薄段外移写成 `4+5: 0.5` |
| `yaxis(ax, ylim, ytick)` | 从 series.json 读死上下界与步长，禁用 autoscale（§3.5.1）|
| `guards.check(fig)` | 出图前两道硬检查：图内全英文 + 任何文字不许压叠。`save()` 自动调用 |
| `titlecheck.verify(title, …)` | B 类标题的判断句与数据核对，矛盾就 raise（§4.4）|
| `roll(periods, cq, window_max)` | 窗口切片（§3.5）。`8` = 两年上限；`None` = 不设上限（图 15–19）|
| `save(fig, path)` | `dpi=150`、`bbox_inches='tight'`、`facecolor='white'` |

**chartlib.py 一旦定稿就不许动。** 真要改样式，改完必须把上一季那批图**用新样式全部重出一遍**，否则同一份报告里会混着两代样式。
